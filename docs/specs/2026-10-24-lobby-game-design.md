# สเปก: ล็อบบี้แบบเกม หน้าจอเดียว (BOF v0.8)

วันที่ 2026-10-24 · สถานะ: อนุมัติและทำเสร็จแล้ว (v0.8) · แทนที่ล็อบบี้ Colour chapters (v0.7, `docs/archive/2026-10-24-lobby-redesign-design.md`)

## 1. เป้าหมาย

**ผู้ใช้บอกว่า:** ล็อบบี้ v0.7 ดูธรรมดา ไม่มีลูกเล่น รกตา และทำให้เข้าถึงระบบกับเริ่มเล่นยาก

**สาเหตุที่เห็นจากหน้าจริง:**
- หน้ายาว 6 จอ ต้องเลื่อนนานกว่าจะถึงส่วนเลือกเด็ค
- แฟ้มสี 5 แฟ้มแย่งสายตาจากปุ่มเล่น
- กฎ "ไม่ประดับ" ทำให้หน้าดูเป็นเว็บข้อมูล ไม่เหมือนเกม

**รอบนี้เปลี่ยนเป็น:** ล็อบบี้เกมหน้าจอเดียวแบบหน้าแรกของเกมมือถือ (แนว HoK Ace) ไม่ต้องเลื่อน มีลีดเดอร์เด่นกลางจอ ปุ่ม "เริ่มดวล" ใหญ่ และกำแพงการ์ดที่ขยับได้อยู่ด้านหลัง

**สำเร็จเมื่อ:**
- จากเปิดหน้าถึงเริ่มเกมใช้ไม่เกิน 2 คลิก (เริ่มดวล → บอท/เพื่อน) ไม่ต้องเลื่อนหน้า
- เปลี่ยนเด็คได้บนจอแรก
- ไม่มีการเลื่อนหน้าทั้งที่ 1440×900 และ 390×844
- กำแพงการ์ดและภาพย่อโหลดรวมไม่เกิน ~2MB ในการเปิดครั้งแรก

**นอกขอบเขต:** หน้ากระดานเล่น, หน้าจัดเด็ค, คลังการ์ด และหน้าต่างของเกม (ตั้งค่าบอท / สร้างห้อง) ไม่เปลี่ยนหน้าตา

## 2. ทิศทางภาพ

- **คงไว้:** ฟอนต์ Kanit (หัวข้อ) + IBM Plex Sans Thai (เนื้อหา) · พื้นน้ำเงินเข้ม `#0b0d1a` · ทอง `#f3c969` · สีระดับความหายากเดิม
- **เลิกใช้:** กฎ "ไม่ประดับ" ของ design-taste-frontend ตามที่ผู้ใช้เลือก ใช้ไล่สีทองบนปุ่ม แสงเรืองบนปุ่มเล่น และขอบทองได้
- **ตรวจด้วย checklist ของ ui-ux-pro-max แทน:**
  - contrast ตัวอักษร ≥ 4.5:1
  - ปุ่มแตะได้ ≥ 44×44px
  - focus มองเห็นชัด
  - ไอคอนเป็น SVG ไม่ใช่อีโมจิ
  - รองรับ reduced motion
- **กฎประสิทธิภาพเดิมใน STATUS.md ยังบังคับ:** ขยับด้วย transform/opacity เท่านั้น · ไม่ใช้ `backdrop-filter` หรือ `mix-blend-mode` กับสิ่งที่ขยับหรืออยู่บนสิ่งที่ขยับ (ต้นแบบใช้ `mix-blend-mode: color` ย้อมสีกำแพง ของจริงใช้ชั้นสีโปร่งแสงธรรมดาแทน)
- **ไม่มีแสงใต้การ์ดลีดเดอร์:** ไม่มีวงแหวนและแสงสีด้านหลัง การ์ดมีแค่ขอบทอง 3px กับเงาดำ

สีประจำเด็ค (ใช้กับชื่อเด็คและสีย้อมกำแพง): จิต `#3ee08f` · เหนือ `#f0a347` · วันสิ้นโลก `#5fd0ff` · เด็คของฉัน = สีของลีดเดอร์ที่ผู้เล่นเลือก

## 4. พฤติกรรม

### 4.1 การเลือกเด็ค
- **ตัวเลือก:** `L01`, `L02`, `L03`, `mine` · `mine` แสดงเฉพาะเมื่อ `localStorage['my_card_game_deck']` ผ่านเงื่อนไขเดียวกับ `loadSavedDeck()` (มี leaderId และการ์ด 20 ใบ)
- **จำเด็คล่าสุด:** เก็บที่ `localStorage['bof_lobby_deck']` · ถ้าไม่มีค่า: ใช้ `mine` ถ้ามีเด็คบันทึก ไม่งั้นใช้ `L01` · ถ้าค่าที่เก็บเป็น `mine` แต่เด็คบันทึกหายไป ให้ใช้ `L01`
- **ตั้งเด็คก่อนเริ่มเกม:** `applySelectedDeck()` ตั้ง `currentDeckConfig` ทุกครั้งก่อนเปิดหน้าตั้งค่าบอท สร้างห้อง หรือเข้าห้องด้วยรหัส
  - เด็คมาตรฐาน: `{ leaderId, mainDeck: [...getDefaultDeckForLeader(leaderId)] }`
  - `mine`: ค่าจาก `loadSavedDeck()`
  - **ไม่เขียน** `my_card_game_deck`
- **หลังบันทึกในหน้าจัดเด็ค** (`#btn-save-start`): ล็อบบี้สร้างรูป "เด็คของฉัน" ใหม่และเลือก `mine` ให้อัตโนมัติ

### 4.2 เริ่มดวล
กด "เริ่มดวล" → `<dialog id="lb-mode-dialog">` มีปุ่มใหญ่ 2 ปุ่ม:
- **"เล่นกับบอท"** → `applySelectedDeck()` แล้วกด `#btn-lobby-bot` เดิม
- **"ดวลกับเพื่อน (สร้างห้อง)"** → `applySelectedDeck()` แล้วกด `#btn-lobby-pvp` เดิม

ปุ่ม `#btn-lobby-bot` / `#btn-lobby-pvp` ยังอยู่ใน DOM (ใน dialog) เพราะ `game.js` และเทสต์ผูกกับ id นี้ ยกเลิก / Esc → ปิด dialog โดยไม่เปลี่ยนอะไร

### 4.3 วิธีเล่น
`<dialog id="lb-howto-dialog">` มี:
- 3 ขั้นตอน (เลือกเด็ค → สร้างห้องหรือเลือกบอท → ดวล พร้อมเวลาโดยประมาณ)
- บรรทัดตัวเลขจาก `LobbyData.rarityCounts()`: "39 ใบ · Legend 5 · SR 12 · R 17 · N 5"
- ปุ่มปิด

## 5. Motion (GSAP core เดิม + CSS)

- **ฉากเปิด (≤ 1.6 วินาที, สั้นลงเมื่อกลับมาซ้ำ):**
  - กำแพงค่อยๆ ปรากฏ
  - การ์ดลีดเดอร์ยกขึ้นจาก y+40 พร้อม scale .92 → 1
  - ข้อมูลเด็ค เมนู และรูปเลือกเด็คทยอยเข้า
  - ปุ่มเริ่มดวลเด้งเข้าท้ายสุด
  - คลิกระหว่างฉากเปิด = ข้ามฉาก ยกเว้นคลิกบนปุ่ม (บทเรียน v0.7)
- **สลับเด็ค:**
  - ไพ่บนกำแพงพลิก (`rotateY` 180°) เป็นคลื่นจากกลางจอออกไปขอบ หน่วงตามระยะห่าง 70ms ต่อช่อง
  - การ์ดลีดเดอร์ใบเดิมหมุนออกซ้าย ใบใหม่หมุนเข้าจากขวา (0.5 วินาที)
  - สีชื่อเด็คและชั้นสีกำแพงเปลี่ยนนุ่ม 0.6 วินาที
  - กดสลับรัวๆ แล้วต้องจบที่เด็คล่าสุดเสมอ (ภาพและข้อมูลตรงกัน)
- **ตอนว่าง:**
  - กำแพงเลื่อนไปมา ±6% ใน 60 วินาที
  - ไพ่บนกำแพงพลิกเป็นใบอื่นในเด็คเดียวกันทีละ 2 ใบ ทุก 1.4 วินาที
  - การ์ดลีดเดอร์ลอยขึ้นลง 10px ทุก 4 วินาที
  - ปุ่มเริ่มดวลมีแสงเต้น
  - ประกายลอยขึ้น 18 จุด (ใช้ canvas ดาวเดิมแทน DOM)
- **พักเมื่อมีหน้าต่างทับหรือแท็บถูกซ่อน · หยุดเมื่อเข้าเกม:** API `window.LobbyMotion` เดิมทั้งหมด (`start`, `stop`, `isRunning`, `isPaused`, `_particle*`)
- **Reduced motion:** แสดงสถานะสุดท้ายทันที กำแพงนิ่ง ไม่พลิกตอนว่าง ไม่มีประกาย สลับเด็คแล้วเปลี่ยนภาพทันที

## 6. ภาพย่อ (ประสิทธิภาพ)

- **สคริปต์ `tools/make-thumbs.js`:** ใช้ Playwright (มีอยู่แล้ว) วาดภาพลง canvas แล้วบันทึกเป็น WebP กว้าง 240px คุณภาพ .8 ไว้ที่ `images/thumbs/<โฟลเดอร์เด็ค>/<n>.webp` (ราว 20–30KB ต่อใบ) รันครั้งเดียวแล้ว commit ภาพย่อ
- **ใช้ภาพย่อกับ:** กำแพงการ์ดและรูปเลือกเด็ค
- **ใช้ภาพเต็ม** (`card.image`) เฉพาะการ์ดลีดเดอร์ใบใหญ่
- **`LobbyData.thumbOf(card)`:** แปลง `images/เด็คจิต/3.png` → `images/thumbs/เด็คจิต/3.webp`
- **ภาพย่อหาย:** `onerror` สลับไปใช้ภาพเต็ม

## 8. การทดสอบ

**ต้องผ่าน:**
- **ไม่มี scroll:** ทั้งแนวตั้งและแนวนอน ที่ 1440×900, 1316×620, 390×844, 320×640 · ไม่มีองค์ประกอบล้นขอบจอ (ตรวจขอบของแต่ละชิ้น ไม่ใช่แค่ scrollWidth — บทเรียน R1)
- **เริ่มเกมได้ใน 2 คลิก:** เริ่มดวล → เล่นกับบอท → หน้าตั้งค่าบอทเปิด
- **เด็คที่ใช้ตรงกับที่เลือก:** สลับเด็คแล้วเริ่มเกม `currentDeckConfig.leaderId` ตรงกับเด็คที่เลือก และ `my_card_game_deck` ไม่เปลี่ยน
- **"เด็คของฉัน":** แสดงเมื่อมีเด็คบันทึก ไม่แสดงเมื่อไม่มี · เลือกแล้วเริ่มเกมได้เด็คที่บันทึก · บันทึกในหน้าจัดเด็คแล้วถูกเลือกอัตโนมัติ
- **จำเด็คล่าสุด:** reload แล้วยังเลือกเด็คเดิม · ค่า `mine` ที่เด็คบันทึกหายไปแล้ว ถอยไปใช้ `L01`
- **กำแพง:** แสดงเฉพาะการ์ดของเด็คที่เลือก ทั้งหลังสลับและหลังพลิกตอนว่าง · กดสลับรัวๆ แล้วจบที่เด็คสุดท้าย
- **ฟอร์มเข้าห้อง:** เทสต์ J1, J2, R2 เดิมยังผ่าน และเรียก `applySelectedDeck()` ก่อน join
- **dialog:** ยกเลิก / Esc ไม่เปลี่ยน `currentDeckConfig` · focus กลับไปที่ปุ่มเดิม · กรอบ focus มองเห็น
- **motion:** เทสต์ T/F เดิมที่ยังมีความหมาย (หยุดในเกม, พักใต้ modal, ไม่ซ้อน, ข้ามฉากเปิด, reduced motion, transform/opacity เท่านั้น, ความลื่น p95 ≤ 17.5ms ขณะว่างและขณะสลับเด็ค)
- **ภาพย่อ:** ทุกการ์ดใน DB มีไฟล์ใน `images/thumbs/` · ภาพบนกำแพงใช้ `.webp`
- **ชุดอื่นต้องผ่านครบ:** `ui`, `choice`, `panel`

**ตรวจด้วยตา:** ภาพหน้าจอที่ 1440 / 390 และ checklist ก่อนส่งของ ui-ux-pro-max

## 9. ความเสี่ยง

- **กำแพง 60 ใบพลิกพร้อมกันอาจกระตุก** → ใช้ภาพย่อ, `will-change: transform` เฉพาะตอนพลิก และวัดความลื่นในเทสต์
- **แสงเต้นของปุ่มเริ่มดวล:** ต้นแบบใช้ animation ของ `box-shadow` ซึ่งวาดใหม่ทุกเฟรม → ของจริงใช้ชั้นแสงแยกที่ขยับด้วย opacity/scale
- **id ที่โค้ดเกมพึ่ง:** คงไว้ตาม §7 และตรวจด้วยเทสต์ทุกชุด
